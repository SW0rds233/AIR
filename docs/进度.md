## 1. 系统边界与目标

用户以自然语言提出研究方向或问题，也可附题面、文献、案例与数据。系统应理解问题类型、约束与授权，
自主形成研究路线，在必要阶段检索与复查资料，建立模型、推导并核验条件性结论，提出可实施的仿真/实验建议，
最后形成可追溯、可读、经审阅的论文，或**如实降级**为条件性报告 / 研究备忘录。

当前阶段**不自动实施新实验、不训练、不投稿**。任何任务若缺资料授权、工具能力或可核实依据，
必须保留未决/条件性结论 —— 不能用"智能体已运行完毕"替代科学正确性。

## 2. 当前架构（唯一性约束）

| 维度 | 唯一入口 | 说明 |
|---|---|---|
| 外层运行 | `graph/research_graph.py`（`TeamRun`）+ `graph/team_session.py`（`TeamSession`） | 主控 `SupervisorAgent` + 七个角色：Evidence / Modeling / Reasoning / ValidationPlanning / Writing / Figure / Review |
| 科学状态提交 | `research/commit.py`（`ResearchCommitService`） | 对象、验证状态、证据冲突与失效传播的唯一提交边界 |
| 文稿表示 | `publication/schemas.py`（`Manuscript`） | 同一 IR 渲染 Markdown 与 LaTeX；图表按 run/哈希校验入包 |
| 排版与编译 | `publication/render_latex.py` + `publication/compiler.py` | `xelatex`；等级按**编译事实**判定，不以"看起来有 PDF"替代 |
| 知识底座 | `kb/service.py`（`KnowledgeService`：search / read / resolve） | 所有召回分支都返回可回原文的定位；命中不自动建立支持关系 |
| 判定层 | `research/acceptance.py`、`research/delivery.py` | 零 LLM；`supported` 需「必要义务全闭合 + 与原命题对齐的有效验证记录」 |
| 交付门槛 | 研究有效性门槛 + 论文表达门槛 | 三级别：研究备忘录 / 条件性研究报告 / 论文草稿 |
| 领域知识 | `src/rag/domain_terms/<domain>.md`（数据文件） | **代码不含领域知识**；新增领域 = 新增一份词表，无需改代码 |

## 7. 踩过的坑（别再踩）

1. **对象归属必须读 `_scope`**：载荷里 `problem_id` 为空会导致同项目两个问题互相看得到对方结论。
2. **`run_id` 必须唯一**：曾用"主题 + 秒级时间戳"，同秒两次运行混在一起。
3. **团队运行必须真的冻结快照**：只写交付包目录不写对象库时，界面显示"已冻结"而 `fork` 报找不到快照。
4. **交付形态要求的每个角色都必须有计划任务**：子问题表与 `_DELIVERABLE_ROLES` 对不上会出现"任务全跑完、一条结论都没有"。
5. **依赖已终止的下游必须能继续**：`settled` 除按"角色+目标"文本键匹配外，还要包含有成果行的任务。
6. **提交口重建载荷会丢元数据**：`_normalise_*` / `_apply_*` 重建 dict 时必须显式搬运字段。
7. **候选种类未登记 = 整条任务失败**：新增可写对象种类要同时登记 `OBJECT_KINDS` / `WRITABLE_KINDS` / `KIND_MAP`。
8. **删旧模块前先确认"新家覆盖 ≥ 旧"**，并把提示词里的规则迁到活的那一份。
9. **不要用内联 Python 传含引号的长字符串**（Windows/`pwsh` 引号地狱）——写临时脚本文件执行，用完删除。
10. **`AgentBase.blocked()` / `partial()` 的参数必须覆盖调用方实际传的**，否则整条任务失败。
11. **跨主题共享目录是新领域的污染源**：下载目录、`outputs/` 等共享位置不得作为新主题的语料来源。
12. **不要在代码里列举学科名词判断"是不是数学题/是不是形式化"**：换措辞就失效；用结构判据（参数元组、量词、命题策略字段）。
