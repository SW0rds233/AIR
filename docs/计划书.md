# AI for Research(AIR)计划书：下一版本构建计划

更新日期：2026-10-03  
依据：本地源码、现有计划及进度文档、测试、真实运行与生成稿件。本文只列**下一版本仍需解决的事项**；历史修复不再作为开发任务。

## 1. 目标与边界

用户可仅用自然语言给出研究方向或问题，也可附精准的问题文件与指定资料。AIR 应在用户授权的资料范围内，自主识别研究意图，查证相关研究，形成可追溯的模型、假设、命题和推导；遇到新前提、反例或知识空白时继续检索与修正，最终输出**逻辑可靠且人能读懂**的论文草稿，或明确说明未决原因的研究报告。对需要经验验证的结论，本版只提出可执行的仿真/实验建议，**不实际执行实验、仿真或投稿**。

成功不等于“生成完整论文 PDF”或“所有测试通过”。核心门槛是：文献在建模和推导时被正确使用；结论与前提、适用域、证据、验证状态一致；文章能清楚解释研究问题、为什么选这条路线、每一步为什么成立、与已有工作有何关系。找不到可靠来源或证明时必须收缩结论或报告未决，不能用流畅文字填补。

## 2. 本轮对照已有计划的结论

现有源码已经建立输入快照和附件 hash 校验、流式限额上传、命题/义务/证书链、四级交付、期刊式章节与 PDF 编译、引用门槛和基础前端会话入口。此处原引用 `AI for Research(AIR)计划推进情况.md`（2026-10-07 已并入 [`docs/进度.md`](进度.md) §4）：该文件记录了 854 个 Python 测试、73 个前端测试及两次真实模型运行；这些是**已有记录**，本次未复跑全量测试。不能将旧计划 R1–R7、S1 的组合设计命题化及 PDF 格式补全继续列为“尚未做”。

但下列能力尚未闭合，且有明确的代码缺陷或设计缺口：

| 优先级 | 发现 | 当前依据与影响 |
|---|---|---|
| P0 | 自主检索可以被整个研究循环跳过 | `src/research/loop.py::_retrieval_requests()` 在 `knowledge_available=False` 时直接返回空；即使 `source_policy=autonomous` 使 `retrieval_available=True`，也没有检索请求。用该实际方法做最小复现：无本地知识库得 0 个请求，有本地库才得 1 个。真实运行 `outputs/research/cdreal2/snap-fdb539f5/decisions.jsonl` 只选推导、校验和综合，未出现 `retrieve_targeted`。 |
| P0 | “发表前检索”无法纠正先前推导 | `src/graph/theory_pipeline.py` 先 `engine.finalize()`，后 `gather_publication_evidence()`；后者主要供相关工作和引文使用，不回写冻结研究快照。检索到相反定理、缺失前提或已有同等结果，不能在同一研究链中修正命题。 |
| P0 | 通用论文入口会输出组合设计专用内容 | `src/research/publication_paper.py` 的摘要、关键词、引言和第 2 节固定写 2-设计、计数条件、Fisher/Bruck–Ryser–Chowla。用非组合设计的 `ResearchSpec` 调用 `build_publication_paper()` 仍得到这些段落；这是语义错误，不只是写作风格问题。 |
| P0 | 删除一个会话会清空共享向量库 | `src/server.py:delete_session()` 清理三个全局 Chroma collection；多项目使用时会损害其他会话的检索资料。修复前应避免在有共享资料的实例中使用该删除入口。 |
| P1 | 多标签页事件与断线重连不可靠 | `session_events()` 虽声称按日志供每个标签页独立读取，回放后实际仍从同一个 `session.events` 队列消费；两个订阅者会争抢事件。`connected` 使用未写入日志的自增 SSE ID，可能与下一条真实事件同号；前端 `lastEventId` 又是跨会话全局变量。 |
| P1 | 历史会话的“恢复”与“切换”上下文不一致 | `switchToConversation()` 会加载模式、项目、问题；`resumeConversation()` 只设置线程 ID 并清空日志，可能把新事件显示在上一个项目工作台。会话记录也未持久化事件日志与中断答复去重状态；checkpoint 降级到内存时仅打印警告。 |
| P1 | 成文门槛偏格式，正文仍像验算日志 | `publication_gate()` 核查章节、编号、引文和占位符，未核查跨章节结论一致性、定理前提或段落的论证功能。`THEORY_LONG_FORM` 文稿只被追加为附录 B，而非融入主文。真实生成稿 `outputs/research/fmtfinal/snap-999cdf22/publication.md` 的第 3 节是判定条目列表、结论主要复述命题数量，已有工作为空；虽可追溯，却尚非理想的科研叙事。 |

另有已知边界：`question_planner.py` 的 LLM 候选与契约校验尚未完全统一；真实跨领域迁移、形式化忠实度、引用是否支持所用前提仍缺独立人工评审。这些应进入验收，而不是在计划里重做已有输入工程。前端本轮 `tsc --noEmit` 通过，只说明类型检查通过，不代表会话行为正确。

## 3. 下一版本工作包

### A. 把文献查询前移到“研究动作”，并允许中途触发（P0）

**目标。** 文献是研究时用于确定定义、已知结论、适用前提和新颖性边界的输入，而不是论文收尾的装饰。不能强制每题联网：`user_kb`、`autonomous`、`both`、离线/无权限应保持原有授权语义；数学自足题也可说明为何不需要外部来源。

**构建。**

1. 在研究开始时从 `ProblemContract` 产生“知识需求”：核心术语定义、可用定理/模型、已知反例、最接近的结果与适用条件。对可检索需求先执行有界的发现检索，保留查询、范围、时间、来源版本和未找到的内容，再决定形式化路线。
2. 将 `_retrieval_requests()` 的可行性判断改为“策略允许且存在可用检索源”，区分本地库索引与外部检索能力；不再用 `knowledge_available` 一票否决自主检索。`retrieve_targeted`、`read_source`、`extract_result` 分别拥有正确前置条件，UI 不展示实际上无法执行的动作。
3. 在模型、命题或证明每一步产生新定义、缺失前提、与已有结果相似、来源冲突时，生成带用途的定向查询；新资料先成为候选证据和可核对的来源卡（原文定位、定理陈述、变量域、条件、版本、可信度），经验证后才能加入推导。检索结果若改变假设/命题，创建新版本并使依赖的验证与正文失效，不能只补一条参考文献。
4. 结论前再做一次有界的已有工作/反例检索，检查原创性和适用域；现有 `gather_publication_evidence()` 仅保留为**编辑性补全**，不能代替研究检索。无全文、未命中或检索预算耗尽都记录覆盖边界，不能推断“领域无先例”。

**接口建议。** 在 `src/research/` 建立小而清晰的 `LiteratureNeed → RetrievalAttempt → SourceCard → PremiseAssessment` 契约，由 `loop.py` 编排；`src/kb/` 负责授权、检索与原文定位；验证层负责判断引用是否支持当前前提。避免再加一套平行 Agent。既有具名定理登记应与外部文献分开：调用一个已登记定理≠系统原创证明该定理，论文必须如实表述。

**验收。** 无本地库但授权自主检索的题在首轮模型/推导前产生真实检索尝试；推导中突然需要未知定理时产生第二次定向检索；相反来源会使命题回退或降级；仅指定库时绝不外搜；检索失败也可继续作条件性推导，但有明确覆盖限制。决策日志能显示“哪次查询改变了哪个前提/结论”。

### B. 重构论文主文：跨领域正确、可读、可复核（P0/P1）

**先修错误。** 将 `publication_paper.py` 中 2-设计专用的摘要、关键词、引言、问题形式化移出通用 renderer；设计领域材料只由该领域的 `ProblemProfile/ResultProfile` 或领域插件提供。未知领域只写已得到的对象、方法、限制，不自动假定存在“经典必要条件”。对组合设计既有稿件保留回归。

**主文写作链。** 冻结研究图输出 `PaperOutline`（问题—资料与已知工作—模型与假设—方法—结果—讨论—局限）；每节列必要的论证任务、可用命题和来源。写作层生成段落时引用命题 ID、前提与来源卡，解释“为什么使用此方法、为何每一跳有效、结果如何回答原问题”，同时把机器证书、逐条工具输出留在附录。当前“长文附录 B”可作为试验材料，但不应被算作主文质量达标；经核验的叙事内容应写进对应主节。

**增加两道门槛。**

- 程序门槛：摘要、引言、定理、讨论和结论指向同一问题及同一版本命题；变量、量词、假设、结论强度一致；定理引用能定位且适用前提已满足；推导顺序与结果表一致；任何正文声称不得高于验证级别；未执行仿真/实验只出现在“建议”，不写成结果。跨领域套话、与主题不相干的术语和无来源的“首次”断言应失败。PDF/格式门槛继续保留，但不能替代本门槛。
- 人工门槛：由非作者的数学/领域审阅者按固定 rubric 检查问题表述、形式化忠实度、关键推理、引用支持度、可读性和结论限制；专家异议变成可复现失败样例。自动评审只能提示风险，不能自证论文科学正确。

**验收。** 至少三类对比样例：组合设计、另一类数学/理论问题、需要经验验证但本版只出建议的问题。第二类稿件不得出现 2-设计专用术语；同一核心结论从摘要到结论含义一致；删去必要证据/改变假设后正文自动降级；读者无需先读附录即可理解主要论证，且能从正文跳到附录验证。

### C. 修复会话的持久性、事件分发与删除隔离（P0/P1）

**先阻断数据损伤。** 单会话删除只能删该会话拥有的 checkpoint、产出和登记对象；共享向量库与共享 topic 缓存不能因删除一条会话被清空。建立资料所有权/引用关系后才能做定向删除。删除采用清单与结果核对，部分失败明确返回，不假装成功。用两个共享知识库的会话回归：删 A 后 B 可继续检索、恢复和导出。

**统一会话真相源。** 把 `SessionRecord` 明确分成：不可变输入快照、运行/checkpoint 指针、消息与中断状态、单调事件游标、状态与终止原因。应持久化足以重放和去重的事件/中断信息，必要时建 append-only 事件表；启动/恢复时校验 checkpoint 与输入快照，若仅内存 checkpointer 可用，明确标记 `durable=false` 并在 UI 警告，不把该会话呈现为可跨进程恢复。对 `done`、`stopped`、`error` 区分“查看”“恢复/重试”，不要统一设为 running。

**SSE 正确性。** 每个订阅者持有自己的游标，从持久事件日志读取 `seq > cursor`，新事件用通知唤醒而不从单一队列争抢。`connected`/心跳不占业务事件 ID；终止事件写入同一序列。会话切换时断开旧 EventSource，按 `(sessionId, threadId)` 维护或重置游标；前端丢弃旧会话迟到的事件。检测日志截断时显式要求全量状态同步，不能静默跳过。

**前端单入口。** 将 `switchToConversation()` 和 `resumeConversation()` 汇总为 `openSession(sessionId, intent: view|continue)`：先读取记录、设置模式/项目/问题/资料策略/运行，再恢复服务端状态和订阅事件。工作台查询必须带已绑定项目与运行身份；会话历史、事件流和当前工作台来自同一 session。自动重连、刷新页面、另开标签、停止后再打开都走该入口。

**验收。** 双标签页同时看到相同顺序的事件；断网重连不丢中断/完成事件、不重复答复；从项目 A 切到 B 时不会显示或更新 A 的工作台；刷新后资料策略、附件身份和中断状态一致；SQLite 不可用时明显提示不能持久恢复。删除 A 后 B 的来源、checkpoint 和论文均可用。

### D. 让前端呈现“研究正在如何推进”（P1）

不以原始事件流充当科研可解释性。研究工作台建议分为：①当前问题与已确认的目标/条件/资料权限；②研究时间线（已检索的来源与覆盖、当前模型/命题、关键缺口、下一动作与理由）；③结果与论文（已证、被否定、条件性、未决，证据/证书跳转与建议）。文献卡要区分“找到标题”“获得全文”“已核对支持前提”；论文预览显示草稿状态、所依赖的研究快照版本及未通过的门槛。会话列表显示模式、项目、状态、恢复能力、最后事件时间，并把“查看”与“继续”分开。附件中的异常可见性/不可信内容继续保留告警，不混入高优先级研究指令。

先画基于现有 UI 的低成本线框与状态图，再改最易误导的状态和动作；不要为了重新布局牺牲当前可用的上传、确认与工作台功能。浏览器验收包括窄屏、长公式/引文、断线、双标签和历史会话切换；可访问性检查包括对比度、键盘焦点与状态文本。

## 5. 结构调整建议与决策边界

保持现有 `src/research/`（研究状态与编排）、`src/kb/`（授权检索与原文）、`src/verification/`（形式化与前提核验）、`src/graph/`（生命周期）、`src/server.py`（API/会话）、`src/web/`（展示）边界。不要另起一套 Agent 流程。优先把下列接口稳定下来，再酌情拆分文件：

| 所属模块 | 单一职责与输出 |
|---|---|
| `research/literature`（建议新增） | 从研究缺口提出 `LiteratureNeed`；关联 `RetrievalAttempt`、`SourceCard`、受支持的前提和失效范围；不直接宣称证明成立 |
| `research/loop.py` | 对“检索/建模/推导/验证/停止”排序并记录预期信息价值；不将本地库可用性等同外搜授权 |
| `research/publication_*` | 从冻结图生成跨领域 `PaperOutline` 和正文；领域专用写作由显式 profile 注入；引用与断言逐条回链 |
| `server` 的会话存储/事件层（建议抽出） | 原子保存 `SessionRecord`、事件序列与中断答复；按订阅者游标重放；定义会话资源所有权 |
| `web` 的 session controller（建议抽出） | 唯一 `openSession`、会话级游标/取消订阅、状态投影；页面组件只展示已绑定的研究状态 |

需由用户/维护者作出的三项决定：①外部文献源、费用上限和资料授权；②引用现成具名定理是否满足特定题的研究验收，还是要求 AIR 自行证明该定理；③论文目标是内部可审阅草稿还是指定期刊格式。没有这些决定，系统仍可实现通用机制，但不得把对应能力标为已通过。

## 6. 本次核查边界

本次更新只修改本计划书，未改研究代码、未删除会话或数据库、未跑真实模型与全量后端测试。已执行当前前端 `tsc --noEmit`（通过），并对实际 `_retrieval_requests()` 进行最小方法级复现（无本地库时 0 个检索请求）。其余问题由源码调用链、已保存运行记录和生成稿核对；修复完成与科学正确性仍需上述自动回归和独立人审分别证明。
