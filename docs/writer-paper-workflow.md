# Writer 学术写作流程

writer 从已登记的来源、命题、模型、核验、图表和未决项构造写作包。资料库全文读取只针对包内已登记的来源 ID 与来源库；检索命中、摘要和书目信息不会自动成为已确定结论。

写作按三步进行：先用命题状态制定论证大纲；再分节起草，引言、文献、研究设计、模型与方法、结果或候选机制、讨论、结论各承担不同任务；最后根据已经写出的正文生成标题、摘要和关键词。每节记录引用对象 ID，编号由出版渲染器统一生成。无已确定命题时，正文只能给出研究框架、候选机制、验证条件和证据边界。

修订时，writer 使用当前稿件中相应章节、受影响对象、审阅问题和验收要求定向改写。修订过程留在内部问题与版本记录，不进入读者正文。写作无法补足的科学依据转为未决项；writer 对问题的处理标记不能替代 reviewer 的独立复审。

出版前审计会提示未登记来源、无依据的结论、越权证明、悬空章节、修订过程文字和未登记图号。调用额度不足时用同一大纲做一次紧凑起草；模型不可用时生成可追溯的研究骨架，并如实标注其不是已经润色的学术论文。

审稿后修订默认最多 3 次，次数随团队状态保存；每次修订之后仍须由 reviewer 复审。若第三次修订后的复审仍不通过，团队停止继续派发修订，以部分交付和未决项说明原因。修改上限可在团队入口传入 `max_review_revisions`（非负整数）。

正式出版核验与本研究的证据支持关系是两道独立判断：明确标为 `insufficient` 的文献不进入正文结构化引用，即使其出版元数据已核查。正文的“已知”“已证实”“已核验”须能回到已支持命题和有效核验记录；否则 writer 需改为条件性陈述。应用研究里缺少相关来源的理论公式不会自动变成证明义务。
