## 根因与修改

1. **新需求优先于已就绪的写作和审阅。** 主控现在优先执行写作/审阅检查点；写作任务不再与下一批研究任务混派。每个新稿件进入独立审阅，不再等待需求队列清空。收尾预留五轮；如果初稿之后还有研究结果，先综合为终稿，再审阅和有限修订。
2. **推理缺少全局和同源限制。** 默认最多 12 个推理任务，每个根命题链最多 3 次（初次核验、一次编码修复、修复后核验）。新 ID 继承根命题，不重置配额；单次最多登记 3 个候选，派生深度最多 2。达到限制后保留未决项，不把它们标成完成。证据入库后的确定性复核单独计数。
3. **定义检查制造了必需的人工等待。** 不再生成必需的 `definition_scope/manual`；处理旧义务时保留其披露要求，但取消人工阻断。没有编码的理论断言返回具体编码修复需求，不转去等待人工确认。显式 `statement_role=definition` 只有取得当前版本的定义编码证书后，才不再被当成待证定理；其科学状态不会因此升级为 supported。
4. **应用课题中的条件数学被经验来源门槛拦截。** 描述性/定义性数学片段可以独立核验，现实因果效应仍需要经验依据。新增 `formal_spec`，将变量类型、全部前提和结论交给真实 Z3 核验。先检查前提一致性，再寻找结论的反模型。它不能与另一组等式目标混用；证书与前提、结论及变量域绑定，换前提不能复用旧证明。
5. **真实定义编码无法受理。** 定义检查支持 `A(v,t)` 形式的声明和乘积中的 `1[条件]`，同时拒绝未声明符号、元数冲突、任意下标和可执行代码。检查仍只覆盖定义编码，不证明量纲、现实适用性或附带性质。
6. **写作和审阅没有充分使用核验成果。** 写作材料优先呈现已确定结果，并包含完整条件命题和变量域；审阅认可对齐的描述性数学核验证书，不再误报“没有经验来源”。写作要求围绕主结果解释推导和边界，并提出包含对象、观测量、基线、采样和判定标准的实验建议。

当前默认不规划配图；无图稿件的 figure 项不参与评分。正文的悬空图号交回写作删除或改成文字/表格解释。
