## 原因与改动

1. **停止没有到达任务网络等待。** 会话只设置自己的标志；团队任务使用另一个取消令牌。现在会话把停止信号传到团队，任务退出等待后保存结果，停止派发后续任务。会话驱动允许团队完成本地收尾，导出已有正文、TeX、研究对象和未决报告，明确标记部分成果，不再启动 PDF 编译。任务内捕获取消异常也不能把运行误记为成功。
2. **硬退出丢失整轮进度。** 原来只在整批任务结束后保存团队状态，初始状态还保留 `queued`。现在每个任务开始前、完成后都保存；恢复未正常收尾的状态时标记 `interrupted`，只开放未完成任务重试。HTTP 续跑不再直接返回内存中的已结束会话，也不会重复启动仍活跃的线程。进程被硬杀时无法执行导出；恢复检查点发生在显式恢复入口，没有添加启动扫描或后台自动续跑。
3. **审阅定位兼容和调度使有效意见失去作用。** 从旧格式的 `detail/locator` 提取引文，仅在指定的当前正文块中精确匹配后恢复定位；显式错误引文、已删除块仍拒绝。书目元数据修订可直接定位已知文献，不强求正文引文。部分无效意见不再使其余有效意见全部失效，但定位不完整绝不能批准交付。完全无效的当前稿审阅最多再恢复一次，仍失败则封存诊断，禁止再次绕去检索。相同意见复用逻辑 ID 和存储对象 ID，减少重复登记。
4. **核验优先级过低。** 本次条件命题已经有可执行 `formal_spec`，却直到写作和两轮审阅后才排到核验；此前的证据任务被硬杀，核验从未执行。现在第一稿前优先执行一批已有编码的目标，仍受每轮、全局和根命题预算限制，不扩展成无界引理生成。
5. **复合定义被错误当成恒等式。** `Nc-Nv = p*Delta-(cc-cv)` 依赖 `Nc=F-cc` 与 `Nv=F-p*Delta-cv`。把所有变量当独立自由变量会得到无关反例。复合定义现在要求补齐条件编码或拆为命名定义；条件命题明确使用 assertion。包含两条定义前提的版本能由真实 Z3 核验通过。
6. **写作没有收到模型的完整公式。** 中介模型登记了 `d2*S`、`e2*S` 两条直接路径，正文却遗漏。写作材料原来没有传入 `formal_encoding`。现在同时传入模型版本、完整编码、变量域、单位、近似和边界，并要求改变路径时明确增加假设或提交模型修订。
