# 验收用例（计划书 §5）

本目录保存**领域验收题**的输入、人工准备的对照材料说明与判定记录。用例本身不包含
任何由系统生成的结果——结果由每次运行产生，随交付包一起归档。

## 目录约定

```
evals/
├─ rubric.md                 # 交付物复核清单与评审维度
└─ cases/
   └─ <case-id>/
      ├─ case.md            # 输入、背景、人工准备的材料清单
      ├─ runbook.md         # 盲测运行手册：两种资料场景、命名、归档清单、运行前自检
      ├─ failures.md        # 失败案例台账（只追加不删除；"非缺陷"必须写理由）
      ├─ domain_terms.md    # 领域术语表（由领域专家填写，不得由运行时模型代填）
      ├─ expected_notes.md  # 人工事先写下的已知解/反例/特例（评审前**不得**给系统）
      ├─ runs/<日期>/        # 每次真实运行的摘要与指针（大文件留在 outputs/research/）
      └─ reviews/           # 每次评审的填写结果（按日期命名）
```

## 用例编写要求

一个用例必须写清三件事，缺一不可：

1. **人工准备的材料**：资料源（文件与来源版本）、已知解析特例、会推翻过强结论的反例。
   这些材料**在评审前不得提供给系统**，否则无法检验系统的判断力。
2. **期望的能力边界**：系统应当得出的结论强度、应当拒绝的说法（例如不得宣称原创、
   不得把 `unknown` 当成已验证）、以及资料不覆盖时必须显示为未决。
3. **判定方式**：对应 `rubric.md` 的哪些维度；哪些结论可以自动化断言、哪些需要人工记录理由。

## 判定记录要求

每次评审在 `reviews/` 下留一份记录，包含：运行身份（project/problem/run）、
送审材料清单、`rubric.md` 各维度判定、失败案例编号与处理状态。
失败案例**不得删除**，只允许追加处理说明。
