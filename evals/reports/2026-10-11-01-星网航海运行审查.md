## 3. 你问的第 2 个问题：PDF 编译失败

### 3.1 直接原因（日志与文档可逐字对照）

```
manuscript.log:996
! Missing delimiter (. inserted).
<to be read again>
                   l
l.66 ...rall t,\ \forall s \in \mathrm{Comp}\big l
                                                  (S_{\mathrm{CN}}(t)\big r)...
```

`manuscript.tex:66` 实际内容：

```latex
... \forall s \in \mathrm{Comp}\big l(S_{\mathrm{CN}}(t)\big r):\ s \in \mathcal{D}_{\mathrm{CN}}(t) \cup \mathcal{U}(t)
```

TeX 看到的是 `\big` 后面跟字母 `l`，而 `\big` 需要一个定界符 → `! Missing delimiter`；xelatex 带 `-halt-on-error`，**第 66 行即中止**，日志末尾虽写着 `Output written ... (3 pages)`，但那只是中断前的残页 —— 于是 `manuscript.failed.pdf`（改名机制按设计工作，未把它当成可交付 PDF）。

### 3.2 这是**渲染层回归**（P-3），不是模型写错

对照唯一文稿 IR 与生成稿：

| 写法 | 模型原文（`manuscript.json`） | 生成稿（`manuscript.tex`） |
|---|---|---|
| `\bigl` | **43** 次 | 0 次 |
| `\bigr` | **43** 次 | 0 次 |
| `\Bigl` | 2 次 | 0 次 |
| `\big l` / `\big r` / `\Big l` | **0** 次 | **42** 次（分布在 12 行：66, 168, 202, 207, 214, 221, 237, 254, 264, 279, 286, 291） |

即：**模型全部写对，是渲染把它改坏的**。肇事函数是我在 `0df175a`（2026-10-08「四层 LaTeX 规范化」）里加入的：

```
src/publication/render_latex.py::_separate_glued_commands
    word = "bigl"                     # \bigl → 取到控制词 "bigl"
    if word in _KNOWN_TEX_COMMANDS:   # ← "bigl" 不在白名单
    for cut in ...:                   # 最长已知前缀: "big" 在白名单里
        return f"\\{word[:cut]} {word[cut:]}"   # → "\big l"  ✗
```

直接复现（本机实跑）：

```
_separate_glued_commands(r"\bigl(S_{\mathrm{CN}}(t)\bigr)")  ->  r"\big l(S_{\mathrm{CN}}(t)\big r)"
```

白名单现状：`_KNOWN_TEX_COMMANDS` 收了 `big / Big / bigg / Bigg`，**漏了整个 `l/r/m` 后缀家族**：`bigl bigr bigm Bigl Bigr Bigm biggl biggr biggm Biggl Biggr Biggm`。

### 3.3 爆炸半径（不止 `\bigl`）

该规则的本质是"已知命令 + 后缀就拆"，因此**任何以已知命令为前缀的合法命令都可能被拆坏**。用 285 条标准 LaTeX/amsmath 命令实测：

**42 条被拆坏（14.7%）**，其中常见者：

| 被改坏 | 变成 | 后果 |
|---|---|---|
| `\bigl` `\bigr` `\Bigl` … | `\big l` `\big r` `\Big l` | **编译失败**（本次即此） |
| `\bigcup` `\bigcap` `\bigoplus` `\bigotimes` `\bigvee` `\bigwedge` | `\big cup` … | **编译失败**（同为缺定界符） |
| `\kern` | `\ker n` | 编译失败 |
| `\caption` | `\cap tion` | 编译失败 |
| `\multicolumn` | `\mu lticolumn` | 编译失败 |
| `\includegraphics` | `\in cludegraphics` | 编译失败 |
| `\middle` | `\mid dle` | 编译失败 |
| `\limsup` `\liminf` `\argmax` `\argmin` | `\lim sup` `\arg max` … | **能编译但语义已偏**（静默） |
| `\leqslant` `\geqslant` `\subsetneq` `\doteq` | `\leq slant` … | 编译失败 |
| `\rightharpoonup` `\leadsto` | `\right harpoonup` … | 编译失败 |

`tests/test_pdf_compilation.py` 当时只覆盖了"**长已知命令不得被拆**"（`\textwidth`）这一面，**没有覆盖"合法命令恰好以已知命令为前缀"**这一面 —— 这正是漏网的原因。

### 3.4 修复方向（尚未实施）

1. **补全白名单**：把 `\big*/\Big*/\bigg*/\Bigg*` 全家族及上述被拆坏的标准命令加入 `_KNOWN_TEX_COMMANDS`（该函数对整词命中会原样返回）。
2. **收窄拆分规则**：只在"前缀属于**关系/二元运算符**集合"且"后缀是 1–2 个字母"时才拆（本次全部真实粘连样本 `\leqz \leqL \leqRH \leqa \leqf \geqN \lld` 都满足；而 `big/lim/ker/cap/mu` 等不属于关系符，`slant/width/arrow` 等后缀过长）。宁可漏拆让编译如实报错，也不要静默改坏或改偏。
3. **加语料回归**：把这份 285 条标准命令清单做成测试，断言 `_separate_glued_commands(cmd) == cmd`（逐条），并保留 `\leqz → \leq z` 阳性样本。

### P-4【严重，但方向相反】交付门槛用**子串匹配**判定"正文出现实验结果"

实测本次稿件：

- `"实验结果"`：**0 次**
- `"实测"`：**8 次，全部是"需要实测 / 不给取值"这类方法论表述**：
  - 「后文把它列为需要**实测**与认证核查的变量」
