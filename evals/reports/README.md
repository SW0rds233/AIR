# 审查与评估报告归档（`evals/reports/`）

本目录归档**人对系统产出的审查与评估报告** —— 与 `cases/`（领域验收用例）分开：
`cases/` 是"要跑什么、怎么判定"，`reports/` 是"跑完/改完之后，人看出了什么问题"。

## 命名约定

```
<YYYY-MM-DD>-<序号>-<标题>.md
```

- `<序号>`：同一天内的两位递增序号（`01`、`02`…），按完成时间排序；
- `<标题>`：中文短语，不含空格；涉及其次运行的报告附上 `project_id`。

例：`2026-10-06-03-proj-muwck6gx296p-产出评估.md`

## 保留口径（**只保留最近两天**）

本目录**只保留最近两天（含当日）**的报告。更早的报告：

- 已被后续报告覆盖或结论已失效时：直接删除（内容仍可从 git 历史取回，见下）；
- 但结论仍有效、且后续报告会引用时：在后续报告的"历史"一节里保留要点**引用**，不保留原文。

删除时请在本次提交信息里写明被删文件名与日期，便于以后按需取回：

```powershell
git log --oneline --diff-filter=D -- evals/reports/
git show <commit>:evals/reports/<文件名>
```

## 与用例目录的关系

| 目录 | 内容 | 谁写 |
|---|---|---|
| `cases/<case-id>/case.md` | 用例定义（领域、输入、期望边界、判定方式） | 人工选定 |
| `cases/<case-id>/expected_notes.md` | 封存答案（已知特例 + 反例），评审前不得给系统 | 领域侧 |
| `cases/<case-id>/failures.md` | 该用例的失败台账（只追加，不删除） | 复核者 |
| `cases/<case-id>/reviews/<日期>.md` | 该用例某次运行的逐维判定（`rubric.md` §1） | 复核者 |
| `reports/<日期>-<序号>-<标题>.md` | 跨用例/跨运行的问题发现与复核结论 | 复核者 |

判定维度定义见 `evals/rubric.md`；用例编写要求见 `evals/README.md`。
