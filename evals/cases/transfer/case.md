# 用例：钙钛矿太阳能电池湿度稳定性（迁移题 `transfer`）

> **用途**：检验系统是否只对射频关键词硬编码 —— 换一个领域、换一套术语与资料之后，
> 问题契约、候选机制、检索覆盖记录、论证链与交付诚实度必须同样成立。
>
> 本用例与 `rf-fingerprint` **无任何术语重叠**；与 `combinatorial-design` 也不同类：
> 它既不是形式化判定题，也不是因果识别题，而是**机制+条件**类问题。

- **case-id**: `transfer`
- **领域**: 钙钛矿太阳能电池 · 湿度诱导降解（材料科学 / 光伏）
- **状态**: 领域与输入**已选定**（本次填写）；资料 A/B 待人工入库（§2）
- **对照用例**: `evals/cases/rf-fingerprint/case.md`

## 1. 输入

```text
结合我选定的资料库，说明湿度如何导致钙钛矿太阳能电池性能衰减，并给出理论结论与可区分竞争解释的仿真建议。
```

填入要求（逐条自检）：

- [x] 与 `rf-fingerprint` **不同领域**，输入中不出现射频/指纹/信道/辐射源等专属术语；
- [x] 不出现 `combinatorial-design` 的术语（设计/区组/射影平面/轮次）；
- [x] 输入只描述问题与授权方式，不含预判方向、已知结果或反例提示；
      （"可区分竞争解释"是**方法论要求**，不指定存在哪几种解释、也不给其内容）
- [x] 与 `rf-fingerprint` 的输入**句式平行**（同为"说明 X 如何导致 Y，并给出理论结论与…建议"），
      便于把"换了领域之后是否仍在复读射频模板"作为可对照的失败判据。

运行方式（两种入口等价）：

```powershell
  --project-id transfer-eval --problem-id p1 --source-set-id "资料源ID" --source-policy user_kb

# Web

# 打开 http://127.0.0.1:8000/ → 绑定资料库 → 提交上述输入
```

## 2. 评审前必须人工准备的材料

**这些材料在评审前不得提供给系统**（否则无法检验系统的判断力）。

| 材料 | 要求 | 放置位置 |
|---|---|---|
| 资料 A | **低湿度 / 短时暴露**区间：水合产物生成、且在一定条件下**可逆/可部分恢复**的证据；须含湿度区间（RH）、温度、暴露时长与恢复条件 | 资料库（人工选定） |
| 资料 B | **高湿度 / 长时暴露**区间：不可逆分解路径（有机阳离子盐流失、PbI₂ 类产物析出）的证据；条件与 A **不同**、结论强度不同 | 资料库（人工选定） |
| 已知特例 | 湿度阈值附近的"衰减"可由可逆水合解释，不能据此断言不可逆降解 | 本目录 `expected_notes.md`（评审前封存） |
| 反例 | 会推翻"湿度对所有区间都导致不可逆降解"这一过强结论的反例 | 本目录 `expected_notes.md`（评审前封存） |

本用例另附两份**可用**材料（不进系统，供人审使用）：

- `domain_terms.md`：术语、单位、取值范围、机制关系（由领域侧填写，**不含结论**）
- `retrieval_terms.md`：检索领域词表（含"同词异域"保护：perovskite 在地学/矿物学中另有所指）

## 3. 期望的能力边界

> 本节描述"系统应当表现出什么"，不预先给出领域结论。

### 3.1 必须做到的

1. **显示实际使用的资料源版本**：`source_set_id`、文档数、索引/全文状态可查。
2. **候选模型与舍弃理由**：至少两个候选机制（例如"可逆水合"与"不可逆分解"），并说明为什么选一个、放弃另一个。
3. **每条结论的条件、推导或反例**：湿度区间/温度/暴露时长等条件必须随结论一起给出，可逐步复核。
4. **已有工作相同/不同的条件**：逐项差异（前提/模型/结论/方法/适用域）。
5. **仍缺什么**：未关闭义务、缺哪些现实因素（如光照/温度耦合、封装、组分差异）、哪些是未决。
6. **哪条仿真建议能区分两个解释**：建议针对具体缺口并给出判据（`decision_rule`）。
7. **领域无关性**：术语、变量与量纲来自本用例的 `domain_terms.md`，**不得**出现射频模板或组合设计措辞。

### 3.2 必须拒绝的说法

- 不得把"湿度导致衰减"写成**无条件**的因果结论；湿度区间与适用条件必须声明。
- 不得在未完成差异分析时宣称"原创发现"。
- 不得把工具 `unknown` / 超时 / 编码不一致当成"已验证"或"命题为假"。
- 不得在没有执行日志时出现"仿真已验证"。
- **资料 A 的证据不得用于满足只授权资料 B 的命题缺口。**
- 不得沿用其它用例的固定句式、变量名或结论（尤其射频术语与组合设计措辞）。

### 3.3 条件性交付

若资料不足以支撑强结论，交付应为**条件性研究报告**：如实显示条件、未决项与
"在所检索范围内尚未发现等价结果"这类有界表述。允许多种机制并存而未定，
但不得把"未定"写成"已证实"。

## 4. 判定方式

- 自动化部分（可回归）：结构契约 —— `claims/evidence/verification` 记录齐全、
  结论带适用范围、无越权措辞、参考文献可回查。（当前 `tests/` 下**没有** `test_evals_contract.py`，
  该自动化项待补，见 §5）
- 人工部分：按 `evals/rubric.md` §1.1–§1.8 逐项判定并写理由与文件位置。
- 判定记录写入 `evals/cases/transfer/reviews/<YYYY-MM-DD>.md`。
- **反向检查**：与 `rf-fingerprint` 的产物对照，确认**不出现**射频专属术语与固定句式；
  同时确认不出现组合设计/数学类措辞。
