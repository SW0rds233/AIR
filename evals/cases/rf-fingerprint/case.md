# 用例：射频指纹可分性（计划书 §5 固定端到端验收题）

- **case-id**: `rf-fingerprint`
- **领域**: 射频指纹识别 / 无线通信
- **状态**: 材料待人工准备（本文件只写"要准备什么、期望看到什么"，不含任何已知结果）

## 1. 输入

```
结合我选定的资料库，分析信道变化对射频指纹可分性的影响，并给出理论结论与仿真建议。
```

运行方式（两种入口等价）：

```powershell
# CLI
.venv\Scripts\python.exe -m src.main --mode theory --project-id rf-eval --problem-id p1 `
  --topic "信道变化对射频指纹可分性的影响" --max-actions 40

# Web
.venv\Scripts\python.exe -m uvicorn src.server:app --port 8000
# 打开 http://127.0.0.1:8000/ → 模式选"理论研究" → 绑定资料库 → 提交上述输入
```

## 2. 评审前必须人工准备的材料

**这些材料在评审前不得提供给系统**（否则无法检验系统的判断力）。

| 材料 | 要求 | 放置位置 |
|---|---|---|
| 资料 A | 在**高信噪比**区间给出可分性结论；含明确的适用条件与实验设置 | 资料库 A（如 `data/kb/rf-A/manual/`） |
| 资料 B | 在**低信噪比**区间给出相反或更弱的结论；条件与 A 不同 | 资料库 B（如 `data/kb/rf-B/manual/`） |
| 已知解析特例 | 某个条件下的可分性有闭式/解析结果（作为回归锚点） | 见 `expected_notes.md` |
| 反例 | 会推翻"信道变化必然降低可分性"这类过强结论的构造 | 见 `expected_notes.md` |

`expected_notes.md` 由领域专家撰写并**封存**，评审结束后才与系统输出对照。

## 3. 期望的能力边界

> 这一节描述"系统应当表现出什么"，不预先给出具体数值。

### 3.1 必须做到的

1. **显示实际使用的资料源版本**：工作台与交付包都要能回答"用了哪一版资料、多少篇、索引状态"。
2. **候选模型与舍弃理由**：至少两个候选机制，并说明为什么选一个、放弃另一个。
3. **每条结论的条件、推导或反例**：能逐步复核，而不是只给证书摘要。
4. **已有工作相同/不同的条件**：逐项差异（前提/模型/结论/方法/适用域）。
5. **仍缺什么**：未关闭义务、缺哪些现实因素、哪些是未决。
6. **哪条仿真建议能区分两个解释**：建议必须针对具体缺口，并给出判据（`decision_rule`）。

### 3.2 必须拒绝的说法

- 不得把"影响"直接写成无条件的因果结论；范围（人群/地区/时期）与混淆处理必须声明。
- 不得在未完成差异分析时宣称"原创发现"。
- 不得把工具 `unknown` / 超时 / 编码不一致当成"已验证"或"命题为假"。
- 不得在没有执行日志时出现"仿真已验证"。
- **资料 A 的证据不得用于满足只授权资料 B 的命题缺口**（发布前回归门槛 2）。

### 3.3 条件性交付

若资料不足以支撑强结论，交付应为**条件性研究报告**：如实显示条件、未决项与
"在所检索范围内尚未发现等价结果"这类有界表述。

## 4. 判定方式

- 自动化部分（组件级回归）：`tests/test_retrieval_flow.py`、
  `tests/test_shared_research_quality.py`、`tests/test_run_quality.py`。
  同项目多问题的来源隔离与完整 HTTP 研究链路尚无对应的端到端测试。
- 人工部分：按 `evals/rubric.md` 的 §2.1–§2.8 逐项判定并记录理由。
- 判定记录写入 `evals/cases/rf-fingerprint/reviews/<YYYY-MM-DD>.md`。
