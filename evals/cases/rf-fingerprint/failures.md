# 失败案例台账：射频指纹可分性（`rf-fingerprint`）

> 依据 `evals/rubric.md` §3。**首轮失败报告**是迭代 I-1 的产物之一：本文件记录真实失败项
> （资料覆盖不足、检索无命中、全文缺失、空引文成强支持、论证归属错误……），
> 而不是一份"看起来完整"的评审记录。
>
> 运行手册见 `runbook.md`；维度定义见 `rubric.md` §2。

## 1. 表结构（与 `rubric.md` §3 一致）

| 编号 | 日期 | 维度 | 现象（含文件/行位置） | 期望 | 处理 | 状态 |
|---|---|---|---|---|---|---|
| R-001 | | | | | | |

- **编号**：`R-NNN`，递增、不复用、不重排。
- **日期**：发现日期，`YYYY-MM-DD`。
- **维度**：取值必须是 `rubric.md` §2 的维度之一 —— 研究意图 / 资料与来源 / 模型忠实度 /
  论证与验证 / 引用与差异 / 仿真或实验建议 / 写作缺口回流 / 交付诚实度。
- **现象（含文件/行位置）**：写清是哪个文件（有行号更好）、哪次运行（`run_id`），
  以及可复核的观察，不写"质量不佳"这类无法验证的判断。
- **期望**：按 `rubric.md` 对应维度应当表现成什么样。
- **处理**：修复动作、追加的测试名、或复议结论。
- **状态**：取值见 §2。

## 2. 状态取值

`待处理 / 已修复(测试名) / 判定为非缺陷(理由)`

## 3. 纪律（必须遵守）

1. **`判定为非缺陷` 必须写理由**：状态写成 `判定为非缺陷(理由)` 时，括号内理由不得为空，
   并须给出依据（对应 rubric 维度 + 文件位置 + 为什么不算缺陷）。留空理由的记录视为"未处理"。
2. **历史记录只追加不删除**：已登记的编号、日期、现象不得修改或删除；修复与复议通过
   追加"处理/状态"说明完成。编号不得回收，行不得整行删除。
3. 每条 `rubric.md` 的 `不通过` 项都必须有一条编号记录，不得只写在评审记录正文里。
4. 同一现象在后续轮次复现时，**新增一行**并引用原编号，而不是覆盖原记录。
